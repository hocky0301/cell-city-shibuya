# CELL CITY: SHIBUYA

**渋谷を、Cellの魂でレンダリングする。**

『2026年、PS3を開発する——1行もコードを書けない人間が、AIと組んで「開発地獄」と呼ばれたPS3に挑み、15年間誰も開けられなかった扉をこじ開けた』へのオマージュとして、AIと組んで一晩で作ったWebGLデモ。

国土交通省 **Project PLATEAU** の3D都市データ（渋谷区）から焼いた **7,770棟**を、PS3の Cell Broadband Engine の構造にならってブラウザ上で動かしている。

## なにが「Cell」なのか

見た目だけのオマージュではなく、**実行の構造をCellに寄せてある**。

| Cell B.E. (2006) | このデモ (2026) | 実装 |
|---|---|---|
| PPE (汎用コア) | メインスレッド — ジョブの分配と描画 | `src/main.js` |
| SPU ×6 | **Web Worker ×6**（`N_SPU = 6` のハードコード） | `src/main.js:16` |
| ローカルストア 256KB | 各Workerが **262,144B の上限と LRU 追い出し**を持つ | `src/spu.worker.js:14, 30-40` |
| DMA転送 | 重いペイロードは Transferable でゼロコピー、byteLength を実測積算 | `src/main.js:268, 302` |
| RSX (GPU) | three.js r180 の上に、自前の GLSL ES 3.00 シェーダ | `src/*.js` |
| FIFO dead | lilToon 初回に 1.6 秒だけ再現（演出） | `src/main.js:450` |

SPU が実チップに 8 基載っていて、歩留まりで 7 基が有効、ゲームが使えるのが 6 基だった——その 6 をそのまま採っている。
`navigator.hardwareConcurrency` は見ていないので、コアが少ないマシンでも 6 本立てる。

## 実装したが、発火しなかったもの

**このデモで一番おもしろいのは、たぶんここだ。**

256KB のローカルストア上限と LRU 追い出しは、飾りではなく本当に実装してある。
ところが、渋谷 7,770 棟をこの静的割り当てで載せると——

| SPU | ローカルストア使用量（理論最大） | 充填率 |
|---|---|---|
| SPU0 | 229,112 B | 87.4% |
| SPU1 | 229,023 B | 87.4% |
| SPU2 | 242,426 B | 92.5% |
| SPU3 | 228,975 B | 87.3% |
| **SPU4** | **248,305 B** | **94.7%** |
| SPU5 | 209,212 B | 79.8% |

**上限 262,144 B に、一度も届かない。**
つまり `evictIfNeeded` の while 条件は永久に偽で、**HUD の `E` 表示は構造上ずっと `E0` のまま**だ。

鉄の掟を実装して、渋谷を載せて、**94.7% で止まった**。追い出しは一度も起きていない。

### しかも、超えたとしても追い出せない

`E` が 0 のままである理由は、実はもう一つある。追い出しのループはこう書かれている。

```js
while (lsBytes > LS_CAPACITY && ls.size > 1) {   // src/spu.worker.js:31
```

**エントリが1個になった時点で止まる。**
だから、単一のチャンクが単体で 262,144 バイトを超えた場合、**追い出しても上限を下回れないまま抜ける。**

実際、大きな建物を46棟だけ詰めた合成のチャンクを1つ投入すると **266,432 バイト**に達し、
上限を超えたまま、eviction は起きない。

実機の SPU なら「ローカルストアに載らないものは、載らない」で終わる。
ここでは**上限が、超過を検出しても諦める柔らかいガード**になっている。

> この2つ目の理由は、最初のコード監査では拾えなかった。
> 改めて別の視点でリポジトリを見直し、合成の負荷入力を自分で作って検証したときに見つけたものだ。

なお `chunkMeta`（233チャンク分のAABB）は「レジスタ扱い」としてこの会計から除外し、全ワーカーに複製している。
その意味でも「256KB を厳密に守っている」わけではない。

## HUD の数値はどこまで実測か

| 表示 | 実測か | 補足 |
|---|---|---|
| SPU0〜5 のジョブ時間 | **実測**（`performance.now()`） | 係数 0.2 の EMA で平滑している。生値ではない |
| LS 使用量 | **実測**（`lsSize()` の実バイト） | 上記5配列の合計 |
| DMA 転送量 | **大半は実測**（`byteLength`） | ジョブ指示だけは `jobs.length*4 + 32` の推定。構造化クローンのオーバーヘッドは非計上 |
| eviction 回数 `E` | 実測 | **ただし上記2つの理由で常に 0** |
| fps / draw call / 三角形数 | **実測**（`renderer.info`） | — |
| 「FIFO DEAD」 | **演出**（1.6秒の固定） | 実測ではない唯一の表示 |

窓の点灯状態は 1,150m を超えるとローカルストアから解放し、560m 以内で決定論的ハッシュから再生成する。
**解放されるのは窓の状態だけ**で、建物テーブル（1SPUあたり 21.7〜27.7KB）は常駐したまま。
「再確保」もメインスレッドからの再DMAではなく、**ワーカー内での再計算**。

## これはゲームではない

目的も勝敗もスコアも当たり判定も無い。`score` / `goal` / `gameover` は全文検索で 0 件。
**リソース制約を可視化したデモ**であって、制約がプレイに跳ね返るループは実装されていない。

## 起動方法

依存もビルドも無い。`git clone` して静的サーバを立てるだけで動く（`data/city.bin` 36.8MB と `vendor/three.js` は同梱）。

```bash
git clone <このリポジトリのURL>
cd <clone先フォルダ>
python3 -m http.server 8123
# → http://localhost:8123
```

または `serve.command` をダブルクリック。

## 街の中にあるもの

- **6つのストーリーシャード** — 紫に光る八面体。近づくと原作の物語の章が開く
- **モノリス** — 交差点上空150m。1:4:9。周囲を8つのキューブが回り、6つは輝き、1つは鈍く、1つは死んでいる。
  Cell の歩留まりと同じ構成だが、**これは固定値の演出**で、実際の Worker の稼働状況とは連動していない（`src/monolith.js:50`）
- **山手線** — OSM の線路データから引いている。ただし編成が走るのは長さ 380m 超の 3 経路だけで、**残り 70 経路は未使用**
- **首都高3号線** — 高架の上をヘッドライトの帯が流れる
- **航空障害灯** — 高さ70m以上の建物の上で赤く明滅
- **窓のネオン** — 用途属性が付いている **2,088棟（全体の26.9%）** だけ用途別に色が変わる。残り 5,682 棟は未分類
- **渋谷ヒカリエ 計測高さ 184.7m** — 近づくと実測値が表示される
- **名前のない 230.8m** — スクランブル交差点から東137m・南120mに、**この市域で最も高い建物**が建っている。
  ヒカリエより 46m 高い。名称属性が無いのでランドマークとして登録されず、画面には出てこない
- **XMBの波** — 上空410mを流れる。色はPS3と同じく月替わり

## 技術情報

- **three.js r180** — WebGL2 コンテキスト生成・シーングラフ・ジオメトリ生成・ドローコール発行を担当。
  `src/` に生の `gl.` 呼び出しは 0 件
- **シェーダは 15 本中 14 本が自前の GLSL ES 3.00**。組み込みマテリアルはモノリス足元のリング 1 つだけ（`src/monolith.js:158`）
- **ポストプロセスは自作**（EffectComposer 不使用 — tiny3D を捨てて cellGcm へ降りた人への敬意）:
  ブライトパス→2段ガウシアン→ACES合成、フィルムグレイン、SDTV時は樽歪み＋走査線＋シャドーマスク。
  レンダーターゲット6枚を手で回している
- **SDTVモード**は 854×480 への縮小＋走査線シェーダ。**インターレース（480i）の処理は入れていない**
- **音声は全て WebAudio のリアルタイム合成**（アセットなし）: ブートの和音、都市のドローン、XMBのクリック、FIFO死亡音
- **データパイプライン**（Python / `tools/`）: PLATEAU 3D Tiles → b3dm解体 → ECEF→ENU変換 → 用途・高さ付きチャンクバイナリ
  （glTF の y-up→z-up 変換という古典的な罠を一度踏んだ）
- 建物 7,770 棟のうち **5,920 棟は計測高さ属性**が入っている。残り 1,850 棟は属性値とメッシュ高さが一致しており、
  焼いた後のデータからは実測値かフォールバックかを区別できない
